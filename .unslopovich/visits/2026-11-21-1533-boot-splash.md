# Dr. Unslopovich — bootloader splash

```text
Dr. Unslopovich's diagnosis
Verdict: A handsome frontispiece that cannot say whether the disk passed: the pass and
         fail screens carry the same two words and differ only in hue.
Stack: C bootloader drawing a 320x240 RGB565 panel; base art 4 bpp (16 warm greys) plus
       a 4 bpp mask for one composited label (bootloader/splash_color.c).
Reviewed: the three committed variants (ok, fail, unknown) and the 16-colour preview in
          assets/bootloader/, against bootloader/splash_color.c and the asset README.
          Static screen, owner artwork, recorded device run (6bc6927c..., 6G/iFlash SD).
Score: 14/24 Admitted  Task path 3 · Truth 1 · Native fit ~2 · States 3 · Access 1 · Specificity 4
Performance: Not profiled. Recorded device run: 6.5 s to firmware, splash base is a
             38,400-byte 4 bpp blit plus a 324-byte mask; no per-frame work after paint.

Critical
- assets/bootloader/helikon-os-splash-alpha-hfs-ok.png vs -fail.png: identical words
  ("HFS+ DETAILS") and identical layout; only the label colour changes (green #00BF63
  vs red #FE3131, bootloader/splash_color.c:2477-2520). On a 6G panel, and for any
  colour-blind user, pass and fail are the same screen. The splash's whole job is this
  one bit. -> Change the label text with the state: "HFS+ OK" / "HFS+ FAIL" /
  "HFS+ CHECKING", keeping colour as reinforcement. This changes owner artwork and the
  recorded image hash.
- Contrast of the status label on the #EFEDE5 paper: green 2.08:1, red 3.14:1. The
  green fails even the 3:1 large-text floor and it is the pass case, i.e. the one shown
  most often. -> Darken the green (about #00924A reaches 3.6:1) or set the label in ink
  with a colour accent.

Noticeable
- "HFS+ DETAILS" (README, assets/bootloader) reads as a button or tab and there is
  nothing to press; "DETAILS" promises a screen the bootloader never shows. -> "HFS+
  VOLUME" or "HFS+ CHECK".

Minor
- "VERSION ALPHA" is baked into the art, so the splash can never display the actual
  firmware version or boot state, although the mask mechanism that composites the HFS+
  label would allow it. -> If a version should appear, give it the same runtime slot.

Ask first
- Every fix above rewrites owner artwork and changes the recorded image hash
  (6bc6927c..., device-checked, 2026-11-04), so it needs the owner's approval and a new
  recorded device run. Nothing here can be treated as a code-only change.

Waived
- Engraved landscape, Benguiat wordmark, hourglass ornament, warm off-white paper: owner
  artwork and the project's identity; the font licence gate is already recorded. The
  vintage-book look is the brand, not a template.
- 6.5 s to first paint: recorded device behaviour, not a UI defect to treat here.

Worth keeping
- The HFS+ label is composited at runtime rather than baked, which is exactly the
  structure that makes a truthful status word cheap to add.
- The neutral grey label while probing: the screen admits it does not know yet. Extend
  that honesty to the pass and fail words.
- One mark, one engraving, one rule of type. Nothing on this screen is decoration for its
  own sake.

Not checked
- No 6G panel: colours were checked as the quantized 16-grey representation; on-glass
  readability, viewing angle and brightness were not measured.
- The device run and the image hash were read from the record, not re-verified here.
- The earlier bootloader-design.jpg source was not reviewed; it is provenance only.
```
