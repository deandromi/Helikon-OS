# Dr. Unslopovich — macOS companion

```text
Dr. Unslopovich's diagnosis
Verdict: The shell is honest about being empty and then says so four times, behind a
         welcome screen that gates the app on every launch and is also the only thing
         the menu can open.
Stack: SwiftUI (macOS 14+, Swift 6 tools, language mode 5), one window, no AppKit views.
Reviewed: SplashView (welcome) and CompanionShell (the only content screen), from
          code. The app builds (swift build, 30.9 s) and launches (window observed at
          1120x748), but screenshots were refused: screencapture answered "could not
          create image from rect" (Screen Recording permission), so every visual
          judgement below is read from source, not seen.
Score: 10/24 Intensive care  Task path 1 · Truth 2 · Native fit ~2 · States ~2 · Access ~1 · Specificity 2
Performance: Not profiled and nothing to profile: no data, no lists, two static views.
             Static leads: none. The splash loads a PNG from Bundle.module on every
             appearance with NSImage(contentsOf:), which re-decodes from disk.

Critical
- App/AppModel.swift:7 the splash is shown on every launch; the only way to skip it is
  the terminal flag --skip-splash (:10). Users cannot opt out from inside the app. ->
  Persist the dismissal (@AppStorage) and show the welcome only on first run.
- Design/Theme.swift:12 HColor.faint (#A9A294) measures 2.22:1 on HColor.paper, and it
  is used for real sentences at 9.5-11 pt: RootView.swift:40 "No features are wired in
  this build.", RootView.swift:88 "No feature modules are present in this build.",
  SplashView.swift:70 the pre-release footer. -> Use HColor.muted (4.72:1) for text and
  keep faint for hairlines only.

Noticeable
- App/RootView.swift:31 the main pane explains the build to the user: "The previous
  feature set has been removed. The library, transfer, metadata, podcast, audiobook,
  scrobbler and installer surfaces are gone...", then :40 repeats "No features are
  wired in this build." and the sidebar :88 repeats it again. Three build notes on one
  screen, one of them about files the user never had. -> One line, in the user's voice,
  about what will live here; move build state to About.
- App/RootView.swift:63 a 248 pt sidebar holds a logo and a footer and no destinations.
  The most valuable strip of a 1120 pt window is empty on purpose. -> Collapse the rail
  until there is a first destination, or use it for the one thing the build can do
  (show the welcome, read a build version).
- Features/SplashView.swift:26 a banner, an eyebrow, a display line, a tagline and a
  button, shown before an empty shell on every launch: an interstitial in front of the
  only task. It also repeats the masthead the sidebar already shows. -> First run only.
- App/HelikonCompanionApp.swift:13 the window cannot be smaller than 1120x720, for a
  screen with one paragraph; on a 13-inch display it opens at exactly the minimum and
  cannot shrink. -> Lower to about 720x480 until the content needs more.
- App/HelikonCompanionApp.swift:34 the window has a hidden title bar, a hidden title
  and no toolbar, so the window has no name anywhere; Dock and Mission Control fall
  back to "HelikonCompanion". -> Keep the hidden bar but show the title on traffic-light
  hover, or put the product name in the traffic-light band.
- App/HelikonCompanionApp.swift:21 and Features/SplashView.swift:51 the only two
  controls in the app both open the splash (menu command "Welcome to Helikon
  Companion", button "Show welcome screen"). Nothing else is clickable. -> Remove them
  once the splash is first-run only.

Minor
- Features/SplashView.swift:33 the eyebrow "For Helikon-OS" says nothing that the next
  line does not; it reads as a version placeholder. -> Drop it or make it the version.
- Design/Theme.swift:34 the brand face is .system(design: .serif), i.e. New York, while
  the recorded identity is Manrope + IBM Plex. It is a stand-in, and stand-ins drift. ->
  Record it as provisional in docs/ui.md, or bundle the licensed face.
- Features/SplashView.swift:28 the banner is scaledToFit inside an 820x420 frame and
  then clipped, so some window proportions crop it. -> Give the banner one aspect ratio
  and centre it.
- App/RootView.swift:84 "Pre-release 0.1.0" and Features/SplashView.swift:70
  "Pre-release 0.1.0 · The installer is not available in this build." repeat the same
  fact in two voices. -> One.

Ask first
- App/HelikonCompanionApp.swift:11 .preferredColorScheme(.light) plus AppDelegate
  NSApplication.shared.appearance = .aqua force the whole app, including system menus
  and panels, into light appearance. A paper-only window is defensible for this brand;
  overriding system chrome is a platform convention change. -> Keep the paper window in
  both appearances, or record the light-only decision explicitly.
- Removing the second build note and collapsing the sidebar changes the identity of the
  shell (from "release notice" to "empty app"). That is the owner's call.

Waived
- Warm paper palette and serif display: brand decisions in docs/ui.md / D-23; with the
  mountain mark and hairlines this reads as this product, not as the generated beige
  default.
- A shell with no features: deliberate. The absence is not the finding; what the shell
  says about the absence is.

Worth keeping
- Real Button with .keyboardShortcut(.defaultAction) and .onExitCommand: Return and Esc
  both dismiss the welcome.
- CommandGroup(replacing: .newItem) {}: no dead New Window item.
- One window, closes to quit: right for a utility.
- The app never pretends a feature exists. That honesty is the reason it can be shown at
  all; it only needs to be quieter.

Not checked
- No screenshots: Screen Recording permission is not granted to the shell, so splash and
  shell were reviewed from source. Layout, spacing and banner cropping are estimated.
- Dark mode, largest system text, VoiceOver order: not run.
- Performance: not profiled; nothing loads.
- Detector: detect.js reported 3 fixed-text-size hits (Theme.swift:34, 38, 42), all
  confirmed in context. macOS has no per-app text-size setting, so the real cost is the
  9.5-11 pt sizes, not the missing scale.
```
