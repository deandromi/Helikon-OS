# Host fixtures — plan and hash policy

> Purpose: name the fixtures behind the host tests, how each is generated and
> what result is expected.
> Status: living document; T-004
> Owner: test lead
> Last updated: 2026-11-04
> Source: `docs/testing.md`, `docs/validation.md`, `docs/verification.md`

No disk image, device backup or library file is committed. Every fixture is
generated by a test, a small helper or a documented shell command. Synthetic
fixtures are deterministic buffers built by C test code; images created by
`hdiutil` contain timestamps and UUIDs, so their SHA-256 is recorded in the run
log rather than compared across runs. A fixture is evidence only together with
the command, output and expected result.

## 3. Evidence and hashes

For each run record:

```text
fixture: ID and generator command
image: SHA-256 when a file/image exists, or the deterministic test name
oracle: fsck_hfs / macOS mount / expected error
result: pass or fail, with the full output
scope: host-only, disposable device, or real device
```

Rules:

- Do not commit generated disk images, backups, `.rockpod-rw` files or music.
- A synthetic fixture's source and test name are its identity; an exported copy
  gets a SHA-256 only when it is preserved as evidence.
- A `hdiutil` image hash is run-specific; never compare it across runs as a
  regression signal. Compare the tree and fsck result instead.
- A device fixture must include the model/revision, adapter/card, firmware image
  hash and result in `device-matrix.md`.
- A failed fixture is preserved outside the repository with its hash and output;
  do not "fix" it by formatting or deleting the journal.

## 4. Adding a fixture

1. Pick an ID and class.
2. Add the generator to the owning test or a documented shell helper.
3. State the expected result as an assertion, not prose.
4. Add it to `docs/testing.md` and this table.
5. Run the test with sanitizers and record the command/output in the change
   evidence.

The current fixture suite is host evidence. It does not replace the device
power-cut matrix, adapter matrix or a recorded 6G run.
