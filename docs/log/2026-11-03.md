## Revision after the first hardware report

The first image (`bd0ebc92…`, 66,920 bytes) booted on the owner's 6G and showed
the splash. HFS+ volume and catalog reported PASS, but the report displayed
`llu` instead of the byte count and shifted the write/journal/splash lines. The
read probe returned `-11` (`HFS_ERR_NAME_INVALID`).

Fixes:

- `%llu` -> `%lu` in `report.c` and the partition line. Rockbox `format()`
  supports `%c %s %l %d %u %x`, not long-long.
- Build-script guard rejects long-long conversion specifiers.
- `hfs_catalog_lookup_ascii()` compares the raw UTF-16BE key for a single ASCII
  root name without decoding unrelated names.
- `boot_diag_run()` uses the raw lookup for the root ASCII probe and keeps the
  strict lookup for multi-component paths.
- Tests: 35 HFS+ + 8 bootloader = 43; ASan/UBSan clean.
