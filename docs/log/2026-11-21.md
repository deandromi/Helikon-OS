## Learned

- A whole-buffer codec contract is not just a memory limit: it makes the VFS
  read path unusable, because `hfs_fork_read` is offset-addressed and never
  hands out a mapped window. The source model is the cheapest seam that fits
  both.
- A probe that sees only a head needs a way to say "not yet"; conflating that
  with `FORMAT` either rejects valid files or forces every probe to be
  whole-file. `NEED_MORE` plus "open is authoritative" keeps both honest.
- The verification matrix in the previous handoff listed nine suites; two more
  exist and had been broken for three days. The matrix should be derived from
  `tests/*/Makefile`, not from memory.

## Rejected

- Making every decoder streaming in one change: FLAC and MP3 need buffer
  semantics (frame indexing; libmad `main_data` boundaries) and would have
  turned one reviewable seam into three half-converted decoders.
- A seek-taking source: `read_at` with absolute offsets already matches the HFS+
  and block layers and needs no state in the source.
- Stub `helikon_mp3_codec_ops` for the player/UI suites: it would hide a real
  link requirement and drift from the registry.

## Work (continued, same day: streaming decoders complete)

7. **FLAC pull decoder** (`firmware/codec/flac/flac_decoder.{c,h}`): added
   `struct flac_reader` (resident buffer or source + 8 KiB window,
   `HELIKON_FLAC_WINDOW`), byte access by absolute offset, metadata parsed
   through the same reader, `helikon_flac_open_source()` (requires a reported
   length), `streaming = 1`. Workspace 73,832 B. `flac_codec.c` fills
   `codec->info` at open (a `NEED_MORE` probe fills none) and reports
   `NEED_MORE` when a head ends inside metadata.
8. **MP3 windowed refill** (`firmware/codec/mp3/mp3_codec.c`): 32 KiB window
   (`HELIKON_MP3_WINDOW`), refilled from `stream.next_frame`; the bit
   reservoir is libmad's own copy, so nothing else must be preserved. ID3v2 is
   skipped by reading its header and sync-safe size before the window is
   filled; the final-frame guard pads the window once (`tail_active`) and the
   old standalone tail buffer is gone; refills loop to a full window; a full
   window libmad cannot consume is `HELIKON_ERR_FORMAT` (no loop). Open fills
   `codec->info`; seek re-aligns inside the window via `mp3_next_sync`.
   Workspace 62,856 B.
9. **VFS media adapter** (`firmware/player/vfs_media.{c,h}`): binds an open
   `vfs_file_handle` and stat size to a codec source; `read_at` = absolute
   `vfs_file_seek` + `vfs_file_read`, EOF is a zero-byte read. Composed with
   the registry in `tests/vfs` on the HFS+ fixture.
10. **Suite plumbing**: `tests/vfs` now links the codec layer and the libmad

## Learned (continued)

- This libmad port copies the bit reservoir into `stream.main_data`, so a
  windowed refill is safe as long as it keeps from `stream.next_frame` — the
  same invariant the previous tail buffer relied on, generalized.
- FLAC's CRC pass re-walks each frame, so a streaming FLAC pull is ~2× the
  stream by design; the honest bound is "window-sized requests", not "one
  pass".

## Learned (ID3v2)

- The tag arithmetic belongs in one place: the MP3 wrapper's private copy was
  already correct but duplicated, and any footer/v2.4 fix would have had to
  land twice.

  that refuses: the library would cache a plausible wrong title.
