## Learned

- A whole-buffer codec contract is not just a memory limit: it makes the VFS
  read path unusable, because `hfs_fork_read` is offset-addressed and never
  hands out a mapped window. The source model is the cheapest seam that fits
  both.
- A probe that sees only a head needs a way to say "not yet"; conflating that
  with `FORMAT` either rejects valid files or forces every probe to be
  whole-file. `NEED_MORE` plus "open is authoritative" keeps both honest.
- The verification matrix in the previous handoff listed nine suites; two more
  exist and had been broken for three days. The matrix should be derived from
  `tests/*/Makefile`, not from memory.

## Rejected

- Making every decoder streaming in one change: FLAC and MP3 need buffer
  semantics (frame indexing; libmad `main_data` boundaries) and would have
  turned one reviewable seam into three half-converted decoders.
- A seek-taking source: `read_at` with absolute offsets already matches the HFS+
  and block layers and needs no state in the source.
- Stub `helikon_mp3_codec_ops` for the player/UI suites: it would hide a real
  link requirement and drift from the registry.

## The loader fills the boot-info page (T-059)

1. **Gap.** D-28 had been accepted since 2026-11-04 and `LOADER.md` documented
   the entry ABI field by field, but nothing filled the page: the loader jumped
   with `r0 = 0`, so a firmware had to re-read the disk for facts the loader had
   already verified and the contract only existed on paper.
2. **Writer.** `bootloader/boot_info_page.c/.h` fills the 4 KiB page from a
   `struct helikon_loader_handoff` — magic/version/size, loader version, board,
   image version, load address, size, SHA-256, bootstate sequence and state,
   journal state, flags, loader stage time, CRC-32 over bytes 0–71, and the
   256-byte verified manifest copy. It refuses a manifest copy that disagrees
   with the stated board, image version, load address, size or SHA-256
   (`HELIKON_ERR_FORMAT`) and a short, unaligned or missing page
   (`HELIKON_ERR_ARGUMENT`). The CRC is a documented duplicate of
   `firmware/lib/crc32.c`.
3. **Loader.** `firmware_loader.c` keeps the verified manifest bytes in
   `struct helikon_loader_result`; `helikon_loader_hw.c` builds the page after
   manifest/image verification, passes it in `r0`, and on a refusal shows
   "Boot-info page refused" and jumps with `r0 = 0`, which the firmware parser
   already maps to `NOT_FOUND` and the read-only diagnostic path.
   `journal_state` stays `0` (unknown — only the firmware mounts) and
   `loader_stage_ms` counts from the start of the loader's own work.
4. **Test.** `tests/bootloader/test_boot_info_page.c` round-trips the page
   through the real `firmware/boot/boot_info.c` parser: 24 checks over the
   fields, the zeroed reserved ranges, the four writer refusals, a corrupted
   header, a corrupted manifest copy and a zero pointer.
5. **Build.** `tools/build-loader-bootloader.sh` copies `boot_info_page.c/.h`
   and `firmware/boot/boot_info.h`; `donor-loader.patch` lists
   `helikon/boot_info_page.c`. The SOURCES hunk header was one line short, so a
   re-applied patch silently dropped `hfs_unicode.c` and the link failed; the
   counts were recomputed from the hunk body and the header corrected.
