# 2026-11-22

## Both halves of Disk Mode have an image

**Goal.** A player can be formatted from a laptop with either the firmware or
the bootloader in charge.

**Firmware.** The Disk Mode image grew a confirmation gate — SELECT hands the
disk over, MENU or 30 s powers off — and a status line with the capacity and
the addressing mode. `helikon_board_storage_init_writable()` in the board gives
Disk Mode a writable block device; `helikon_board_storage_attach()` keeps the
read-only flag for everything else. `disk_mode` restore mode clears the
read-only flag on its private copy itself, and the host test now starts from a
read-only device so that clearing is what the write proves. Image: 40,500 bytes,
no `hfs_volume_probe` symbol.

**Bootloader.** `bootloader/hardware/helikon_usb_disk_hw.c` builds the seam the
firmware stack expects over `ata_read_sectors`/`ata_write_sectors`/`ata_flush`,
`udelay` and `PWRCON`, polls `helikon_usb_irq()` instead of reaching into the
donor VIC, asks for SELECT, and calls `helikon_disk_mode_start()` after
`storage_init()`, before any mount. The entry is `noreturn`, so no path can
fall through into the donor's filesystem code. `donor-usb-disk.patch` adds the
sources and the call; `tools/build-usb-disk-bootloader.sh` exports the donor at
the pinned commit, applies it and writes the image and a DFU file.

**Evidence (host and build only).** Image 108,264 bytes, SHA-256
`1955a943…`; DFU 116,400 bytes, SHA-256 `13f549b8…`; `_moveend 0x2203ae40`
against `MOVE_AREA` end `0x22040000`, 20,768 bytes of headroom; two builds
produced identical hashes; the image contains `helikon_usb_init`,
`helikon_disk_mode_start` and the "Helikon Disk Mode" string. `tests/usb` plain
and under sanitizers passes. Every other host suite passes on the merged tree.

**Not attempted.** No device run for either image. Neither has enumerated,
mounted or been formatted. D-56 (VID/PID) is open, so a host sees the
placeholder identity.

## The clock-gate inversion

Auditing the controller against the donor's `usb-s5l8702.c` turned up one
thing that a mock cannot see: PWRCON bits are power-*down* gates, so enabling a
clock clears the bit. `clock.c`, `pmu.c`, `buttons.c` and `ata.c` all do that;
both USB seams set the bit, which gates the OTG and PHY clocks off before the
core is touched. Fixed in `firmware/hal/6g/usb_target.c` and
`bootloader/hardware/helikon_usb_disk_hw.c`; the audit table and the fixed
values live in `usb-device-stack.md` §11. The Disk Mode image is 40,500 bytes
after the fix, the bootloader image 108,264 bytes (SHA-256 `1955a943…`).

## Fuzzing the transport (T-115)

`tests/usb/fuzz_msc` is deterministic: a fixed seed produces the same byte stream
on every host, so a failure reproduces from the printed seed. It drives the real
`usb_msc.c` over a sparse 4 TB fake disk and covers four cases — whole disk,
volume window, read-only device, I/O faults — 162,500 commands per run, and runs
under ASan/UBSan in `make -C tests/usb sanitize`.

What it checks: the CBW is either accepted or refused with `HELIKON_ERR_FORMAT`
and nothing else; the window never moves; no sector outside the window is read
or written; a read-only device takes zero writes; the CSW has the `USBS`
signature, echoes the tag, carries a status byte in range and a residue no
larger than the declared transfer; a failed command leaves a sense key; a device
error is never reported as success; eject only ever comes from START STOP UNIT,
and reading it consumes it.

What it found: a refused CBW used to be dropped silently, with no CSW and no
state, so the host waited out its transfer timeout before resetting the pipe.
`helikon_usb_msc_phase_error_csw()` now builds the 13-byte answer — `USBS`, the
tag echoed from the broken CBW, zero residue, `PHASE_ERROR` — and
`disk_mode.c` sends it before returning to idle. `test_disk_mode` pins that
sequence, including the re-armed CBW afterwards.

Sizes after the change: Disk Mode firmware 40,500 bytes; bootloader image
108,264 bytes, SHA-256 `1955a943…`; DFU 116,400 bytes, `13f549b8…`; `_moveend`
20,768 bytes inside `MOVE_AREA`. Still no device run.
